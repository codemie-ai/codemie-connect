- **AC5 / Spec §3 persist() missing**: `inject_bundled_bin_path` sets the process `PATH` via `unsafe set_var` but never calls `persist()`. The spec (Design §3) explicitly requires calling `persist()` with the shim `bin\` directory to write `HKCU\Environment` and broadcast `WM_SETTINGCHANGE`. Without it, the PATH addition exists only for the lifetime of the app process; it is never written to the registry, so `codemie` is unreachable from any terminal opened outside the installer session. Evidence: pathman.rs new `inject_bundled_bin_path` function ends with `Ok(())` after `set_var` with no `persist()` call.
- **Spec §2 bundle.resources incomplete**: The `tauri.conf.json` `bundle.resources` object declares `bin/codemie.cmd` but omits the `node\node.exe` and `cli\node_modules\@codemieai\code\dist\index.js` target entries. The spec says "the spec fixes the target layout" for all three resource categories; EPMCDME-14505 handles source preparation, not target declaration. Missing entries cannot be added without source files existing, but the spec's intent to declare the full layout here is unmet.
- **Spec §3 probe test incomplete**: `tests_windows_probe::probe_detects_codemie_cmd_shim` asserts `candidate_bin_names` contains `"codemie.cmd"` and that a freshly-created file exists, but never invokes the `probe` closure (or any equivalent function) against the temp directory. The spec requires the test to "assert the probe detects it" — i.e., that the directory-scanning logic actually returns true for a directory containing `codemie.cmd`. Evidence: pathman.rs diff hunk test body has no call to the probe or to `inject_bundled_bin_path` with the temp dir.
